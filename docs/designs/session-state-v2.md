## Object (design item 1)

One object per session **lineage** (the compression-lineage root id), version 2. Python shape:
`hermes_session_state_schema.SessionState` (dataclasses); machine schema: `schemas/session_state_v2.schema.json`,
generated by `scripts/gen_session_state_schema.py` from `JSON_SCHEMA` (a test pins the committed file).

| Field | Meaning |
|---|---|
| `version`, `rev`, `computed_at` | `2`; store-wide monotonic revision; the recompute clock. `rev`/`computed_at` are store-owned and excluded from the digest. |
| `identity` | `{gateway, profile, lineage, tip}`. |
| `session` | `{mode: running\|idle\|failed, turn, processes[], subagents[]}`. |
| `cards` | Owner-qualified key (`<board>/<id>` local, the replica key for remote) → `{lifecycle, blocked_on, detail, parents[], linked, via, run, source{freshness, synced_at}, block_episode, resolution, red, eta}`. Includes each linked local card's dependency closure (`linked: false`, bounded to 200 cards / depth 8). |
| `blocked_on` | `human \| card \| ci \| clock \| deploy \| capacity \| agent \| unknown \| null`. Stale or partial sources are `unknown`, never inferred. |
| `asks` | Open asks not covered by a committed resolution of their card's current episode. |
| `resolutions` | Recorded user actions (last 50), each bound to one `request_id` and one block episode. |
| `header` | `{status, colour, stripe, reason_codes, counts{six sections}, pips[]}`. |
| `sources` | Per reader `{coverage: complete\|unknown, reason}`; a raising reader is unknown, never empty. |
| `next_change_at` | Earliest future instant the object changes with no event (600 s triage threshold, clock waits). |
| `legacy` | Shadow-mode record of the v1 envelope it was reduced from. |

Renderer rule (design item 7): a card whose current block episode has a committed resolution is not red and its
ask leaves `asks`; a later re-block starts a new episode and is red again. An answer resolves only its own request.

## Reducer (pluggable, pure)

`hermes_session_state_reducer.reduce(inputs, *, now, resolutions)`: no I/O, no implicit clock. P1's
`legacy_adapter` takes the session verdict from today's `reduce_status` over the v1 snapshot assembled by the
**same** code the v1 producer uses (`hermes_state_session_status_snapshot.collect_parts` + `assemble`, split out of
`canonical_status` without behaviour change), and derives cards, blocked-on, counts/pips and `next_change_at` from
the same inputs. P2 replaces it via `register_reducer`.

## Store (design items 2, 3, 5)

`hermes_session_state_store.SessionStateStore` in the serving gateway (`hermes serve`; `session_state.enabled:
false` in config.yaml disables it). state.db tables: `session_state` (one row per lineage: tip, rev, digest, body, next_change_at),
`session_state_alias` (every session id → lineage), `session_state_cards` (card key → lineage, linked + closure),
`session_state_resolutions`, `session_state_meta` (store rev). Every recompute is a full collect → reduce →
digest-gated persist → push. The only timer is `next_change_at`; a 5-minute reconciliation sweep recomputes every
row and counts digest changes as missed events (`metrics()["reconcile_diffs"]`). Each recompute compares the v2
header with the stored v1 `outcome_json.status` and logs disagreement to `logs/session-state-divergence.jsonl`.

Event sources (`hermes_session_state_events`): `refresh_outcome` (turn start/end, reap, notice, mute, card
change); every `task_events` commit on every local board and Board replica (cross-process, `data_version` gated,
per-file cursor); replica remote-card listing per session; state.db transcript/outcome writes (turns, subagent
children); the process registry lifecycle wake; user-steps `requests` create/resolve.

## Transport (design item 4) and actions (design item 7)

`hermes_cli/web_routers/session_state.py`: `GET /api/session-state/{id}`, `GET /api/session-state?since=<rev>`
(persisted rows only, no compute), `WS /api/session-state/ws` (`subscribe{keys, since_rev}` → snapshot, then
pushes; clients keep the highest rev per lineage), `POST /api/session-state/actions`
(`{action: unblock|answer|archive|release, session_id, card, episode, request_id, choice_id?, label?, text?}`) →
commits on the local board, records the resolution, recomputes synchronously and returns
`{ok, object, rev, resolution}`. `episode` is required: the card's `block_episode` as shown (null when it was not
blocked). Every transition is fenced to it inside its write transaction (`unblock_task`/`archive_task`/`release`
`precondition`; checked before the answer handler runs), so a click on an ask that was answered and re-blocked
since is refused `stale_episode` and resolves nothing. `answer` goes only through a registered fenced decision
handler (refused without one). `release` acts only on the home-filed `release_target` offer
(`kanban_release.offered`, else `not_offered`) and runs as an explicit human writer
(`human_writer("session-state-action:<request_id>")`), never with the serving process's ancestry.

Reconciliation is bounded: each sweep first prunes the rows (object, card index, aliases, resolutions) of gone
sessions and of sessions ended more than `RETAIN_S` (7 days) ago, then recomputes the next `RECONCILE_BATCH` (64)
lineages round-robin, serving live events between them.

Shadow mode: nothing renders from it in P1.
